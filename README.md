# MarkVault

Просмотрщик Markdown-каталога. Весь код лежит в одном PHAR, а данные — рядом
с ним: `config.yaml` и каталог `.md`. Один и тот же `markvault.phar` показывает
сколько угодно книг: конфиг приходит снаружи, поэтому собирать ничего не нужно.

## Что умеет

- навигация по дереву `.md` с подписями из конфига, сортировкой и скрытием лишнего;
- тёмная и светлая тема, каждая настраивается по CSS-переменным;
- парольная защита отдельных файлов и целых папок;
- Markdown → HTML с подсветкой кода;
- режим свёрнутых папок: ветка с открытым документом всё равно раскрыта.

## Требования

- PHP 8.2 или новее;
- `mbstring` и `readline` — их требует `karelwintersky/arris.toolkit.cli-console`,
  из которого берётся справка `--help`;
- `phar`, если запускается собранный файл.

Сборка идёт в Docker, локально ничего ставить не нужно.

## Быстрый старт

```bash
composer install
php index.php
```

Приложение откроет `config.yaml` из своего каталога и покажет
`content.default_file`. Рабочий пример конфига и каталога — в этом же
репозитории.

## Ключи командной строки

| Ключ | Смысл |
|---|---|
| `-c`, `--config=FILE` | путь к `config.yaml` книги; перекрывает `MARKVAULT_CONFIG` |
| `-V`, `--version` | версия сборки, затем выход |
| `-h`, `--help` | справка: что это, ключи, пример nginx и минимальный конфиг |
| `-v`, `--verbose` | встроенный ключ CLIRunner |

Ключи нужны только под CLI. Под FPM их нет — конфиг приходит параметром
`MARKVAULT_CONFIG`.

Пустой вызов без ключей рендерит книгу, а не показывает справку: так удобно
гонять регрессии и заглядывать в dev-режиме.

Коды возврата:

| Код | Когда |
|---|---|
| `0` | обычная работа и `--help`, `--version` |
| `1` | `config.yaml` не найден или нечитаем; тело ответа — короткое сообщение, путь уходит в `error.log` |
| `2` | ошибка в ключах, например повторный `--config`; текст идёт в `stderr`, `stdout` пуст |

`--config` без значения PHP `getopt` отбрасывает, и вместо ошибки печатается
справка — с кодом `0`.

## Конфигурация

Путь к конфигу выбирается по убыванию приоритета: `--config=`, иначе
`MARKVAULT_CONFIG`, иначе `config.yaml` рядом с `index.php`. Относительный
`content.path` разрешается от каталога конфига, поэтому книгу можно положить
куда угодно.

```yaml
site:
  # Заголовок <title> берётся из первого # в документе, поэтому эта настройка
  # сейчас нигде не выводится — осталась на месте для совместимости.
  title: "Моя книга"

  # заголовок блока навигации
  nav_title: "Документы"       

content:
  # Каталог с документами. Относительный путь разрешается от корня приложения.
  path: ./content             

  # Документ, который открывается, когда в адресе нет ?file=
  default_file: README.md

  # Как показывать папки в навигации: opened | collapsed
  # Ветка с открытым документом всё равно раскрывается автоматически.
  folders: collapsed
  
  # Как папки запоминают раскрытие между переходами: none | per_folder | single
  #   none        не помнить (по умолчанию) — каждая загрузка страницы начинается
  #               с состояния, заданного выше в folders;
  #   per_folder  каждая папка помнит своё состояние в localStorage, открыто
  #               сколько угодно папок одновременно;
  #   single      открыта не более одной папки на уровне: открытие новой
  #               схлопывает остальных соседей, переключение ссылок внутри
  #               папки её не закрывает.
  # Ветка с открытым документом раскрывается в любом режиме.
  folders_remember: single

# Кастомные заголовки для файлов в списке контента
titles:                       
  "README.md": "Главная"
  "Questions/": "Вопросы"

# Сортировка файлов
sort:
  # Каталоги в навигации идут раньше файлов, на каждом уровне: сначала
  # папки по алфавиту, потом файлы по алфавиту. По умолчанию true.
  # false — сплошная сортировка по пути, true - каталоги раньше файлов
  # Есть проблема: этот ключ приоритетнее следующих
  folders_first: true
  
  # в начало списка, в указанном порядке
  before_all: ["README.md"]

  # в конец списка, в указанном порядке
  after_all:  
    - "GLOSSARY.md"

# Список файлов и папок, которые не показывать в навигации
hide:                         
  - index.php
  - vendor

theme:
  # Тема по умолчанию: dark | light
  default: light

  # Тёмная тема, здесь дана для сведения. Поскольку зашита в конфиг по-умолчанию - в реальном конфиге может быть опущена
  dark:
    bg: "#0f1115"
    panel: "#161920"
    text: "#e6e8eb"
    muted: "#9aa0a6"
    accent: "#5b9df9"
    code_bg: "#1e222a"
    border: "#2a2f3a"

  # Светлая тема, здесь дана для сведения. Поскольку зашита в конфиг по-умолчанию - в реальном конфиге может быть опущена
  light:
    bg: "#faf9f7"
    panel: "#f2f0eb"
    text: "#232323"
    muted: "#6b6b6b"
    accent: "#0366d6"
    code_bg: "#f6f8fa"
    border: "#e1e4e8"

# 🔒 Защита файлов паролем.
# Если секция отсутствует или пуста — защита отключена целиком.
protected:        
  # Если пароль не задан или пуст - защита отключена совсем
  password: "password"

  # Показывать ли защищённые файлы в оглавлении. По умолчанию true.
  # При false файлы скрыты от тех, кто ещё не ввёл пароль (у вошедших
  # они видны как обычно), но по прямой ссылке по-прежнему спрашивается пароль.
  visible: true

  # Список файлов (относительные пути от корня контента).
  # Можно указывать как точный файл, так и всю папку (тогда защищены все .md внутри).
  files:
    - "06-longers.md"
    - "Questions/"            # папка целиком
  
  # Метка для защищённых файлов в списке
  lock_icon: "🔒"
  title: "Файл защищён"
  hint: "Введите пароль для доступа"
```

Тонкости, на которые легко наступить:

- `content.folders`: всё, кроме точного `collapsed`, считается `opened`.
- `titles` читается целиком и разбирается вручную. Запрос вида
  `get('titles.имя-файла.md')` вернёт пустое значение — в ключе точки, поэтому
  так не делайте.
- `before_all` важнее `after_all`: файл из обоих списков остаётся в `before`.
- `sort.folders_first` (по умолчанию `true`) раскладывает основную группу по
  уровням дерева: на каждом уровне сначала каталоги, потом файлы, внутри каждого —
  по алфавиту. Именно по уровням, а не по строке пути: иначе папка «Questions»
  встала бы между файлами по общему правилу, а «1 - Альфа» — по цифрам. Сравнение
  идёт по сегментам, поэтому решение «каталог или файл» принимается раньше, чем
  сравниваются имена. `before_all`/`after_all` его не касаются: там порядок задан
  конфигом явно. `false` возвращает сплошное сравнение путей, как было раньше.
- `theme.dark` и `theme.light` содержат один и тот же набор ключей; неизвестные
  ключи игнорируются.
- Всё, чего нет в `config.yaml`, берётся из дефолтов в `app/Config.php`.
- `protected.files` принимает и файл, и папку. Вход хранится в cookie
  `md_docs_auth` на 30 дней (@todo настраивать имя куки)
- `protected.visible: false` убирает защищённые файлы из оглавления у тех, кто
  ещё не ввёл пароль, включая папки, в которых не осталось ни одного открытого
  для гостя документа. Вошедшим файлы видны как обычно. Ключ скрывает структуру
  от гостей, а не доступ: по прямой ссылке файл по-прежнему спрашивает пароль.
  По умолчанию `true`.

## Сборка PHAR

```bash
make phar
```

`build_phar.sh` собирает Docker-образ `phar-builder-markvault` (внутри —
Box 4.5.0), ставит зависимости, кладёт `vendor/_version` с темой и датой
коммита, компилирует `markvault.phar` и тут же проверяет результат через
`php markvault.phar --version`. Докер-образ кэшируется; 
`bash build_phar.sh --rebuild` пересобирает его с нуля.

Внутри архива только `index.php`, `app/` и `vendor/`. Конфиг и каталог `.md`
не попадают — они остаются снаружи.

`make phar` возвращает ненулевой код, если контейнер упал на любом шаге, в том
числе на проверке `--version`. Владелец готового файла при этом всё
равно возвращается вашему пользователю: контейнер работает от root, но
`build_phar.sh` перехватывает выход и делает `chown` сам, а не в цепочке `&&`.
Поэтому `root:root` у `markvault.phar` — признак того, что сборку прервали, и
повод посмотреть последнюю напечатанную строку.

Две особенности, о которых стоит знать:

- локальный `vendor/` после сборки становится «authoritative»: новые классы в
  нём не появятся, пока не выполнить `composer dump-autoload`;
- `index.php` рядом с собранным `markvault.phar` запускает именно phar, а не
  рабочее дерево, — так проверяют сборку, не заглядывая внутрь.

## Развёртывание

Исполняемый файл — сам PHAR, конфиг приходит параметром:

```nginx
location ~ \.php$ {
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME /usr/local/bin/markvault.phar;
    fastcgi_param MARKVAULT_CONFIG /var/www.books/Книга/config.yaml;
    fastcgi_pass unix:/run/php/php8.2-fpm.sock;
}
```

Свои `fastcgi_param` обязаны идти **после** `include fastcgi_params`, иначе
перекроются значения из общего файла. Путь из `SCRIPT_FILENAME` передаётся
как есть — подставлять `fastcgi_index` вместо него не нужно.

PHP-FPM:

- `security.limit_extensions` должен разрешать `.phar`, иначе будет 403;
- `phar.readonly` можно оставить `On` — он запрещает запись, а не запуск;
- пользователь FPM должен читать и `markvault.phar`, и каталог книги;
- после пересборки PHAR нужен reload FPM.

Если `MARKVAULT_CONFIG` указывает на нечитаемый файл, ответ — 500 с общим
текстом, а сам путь уходит в `error.log` и в интерфейс не попадает.

## Структура сырцов

```
index.php              точка входа: ключи, выбор конфига, автозагрузчик
app/
  Application.php      сборка страницы и запуск
  Auth.php             парольная защита файлов и папок
  Config.php           конфиг поверх arris.config, дефолты, тема
  Helper.php           ключи CLI через CLIRunner и выбор config.yaml
  DTO/Document.php     файл или папка каталога
  DTO/Page.php         всё, что передаётся шаблону
  Render/Content.php   сканирование каталога, заголовки, сортировка, скрытие
  Render/Markdown.php  Markdown → HTML
  Render/Navigation.php дерево навигации
  Units/Path.php       работа с путями
  Units/Request.php    $_GET, $_POST, $_COOKIE, $_SERVER
  template.php         HTML, CSS и клиентский JS
config.yaml            пример книги
box.json               параметры сборки
build_phar.sh          сборка в Docker
makefile               цели: `make phar`, `make update`
```
